## 1. 愿景与核心理念

### 1.1 我们解决什么问题

原版 Stardew Valley 的 NPC 是**程序化的木偶**：
- 按固定 schedule 在固定时间出现在固定地点
- 对话是预编写的静态文本，玩家只是对话触发器
- 没有记忆、没有情绪、没有主动性
- 不能帮玩家做事，不能和玩家一起冒险

**ValleyAgent 要让 NPC 从"木偶"变成"有自主意识的虚拟生命"**：
- NPC 有自己的目标、情绪和记忆
- 会主动找玩家玩、送礼物、帮忙干活
- 根据玩家对话内容产生真实的情绪反应和好感度变化
- 能和玩家一起战斗、收菜、挖矿
- 所有行为符合角色性格设定，不跳出人设

### 1.2 核心目标

| 优先级 | 目标 | 说明 |
|-------|------|------|
| P0 | **自主规划** | NPC 自己决定做什么，不是被动等待指令 |
| P0 | **真实性格** | 所有言行符合角色设定（RAG 约束），NPC 不是机器 |
| P0 | **AI 对话** | 玩家和 NPC 的每次对话都是独一无二的，对话内容影响 NPC 行为 |
| P1 | **共同冒险** | NPC 和玩家一起战斗、收菜、挖矿 |
| P1 | **情感连接** | 对话影响好感度，NPC 会记住玩家说过的话 |
| P1 | **社会存在** | NPC 是镇上的居民而不是玩家的宠物：有钱包/背包/交易/雇佣等经济生活，有低摩擦的聊天栏沟通，行动有节奏（动态速度） |
| P2 | **仪式感** | 完成任务有收尾动作，送礼物有完整流程 |
| P3 | **多 Agent** | 暂不实现 |

### 1.3 设计哲学

1. **NPC 不是万能的** — NPC 会受伤、会死、会犯错、不能解决所有问题
2. **NPC 有"内在世界"** — 情绪、记忆、目标，驱动行为的是内在状态而不是外部脚本
3. **决策不阻塞行动** — LLM 决策完全异步，NPC 在等待决策时仍然可以移动和执行操作（✅ v4.1 THINKING 状态已移除）
4. **仪式感创造活人感** — 做事有头有尾，送礼有流程，比单纯的功能更重要
5. **TS 做智能，C# 做执行** — 所有 LLM/RAG/决策/对话由 TS Agent Server（`D:\Source\ValleyAI`，编译为 `valley-ai-server.exe`）完成，C# 只负责游戏操作执行和数据收集
6. **性能优先** — 不能太卡，Token 消耗要可控
7. **AI 的决定必须可追溯** — 程序状态、NPC 思考、导演思考全量留痕；任何 AI 行为事后都能回答"它当时为什么这么想"（支撑调试与未来历史回顾功能）

### 2.1.1 TS Agent 服务器架构（v4.3 现状）

智能层是 TypeScript 服务器（`D:\Source\ValleyAI`，bun workspace 模式）。Bun 编译为单文件 `valley-ai-server.exe`，由 C# `ServerProcessManager` 管理生命周期。

**包结构**：

| 包 | 名字 | 角色 |
|---|---|---|
| `packages/core` | `@valley/core` | Provider-agnostic Agent 框架：agentLoop、LLM provider 抽象、Transport、CircuitBreaker、MemoryBackend 接口、TokenBudget、PerformanceMonitor |
| `packages/stardew` | `@valley/stardew` | Stardew 实现：CLI 入口、Bun WebSocket 服务器、NPC agent、工具、提示词、协议适配器 |

**核心源码文件**（`packages/stardew/src/`）：

| 文件 | 角色 |
|---|---|
| `cli.ts` | 进程入口；解析 CLI 参数/env，启动 server，处理 SIGINT/SIGTERM |
| `server.ts` | `Bun.serve` WebSocket 服务器；装配 NpcPromptLoader + PromptBuilder + VercelAIProvider + StardewAgentRegistry + ProtocolAdapter |
| `protocol-adapter.ts` | 按 `type` 字段路由 JSON 消息；dialogue 失败时调用 rule-engine fallback |
| `stardew-agent.ts` | `StardewAgent` — 包裹 core `Agent` 执行一次对话 run；构建工具、系统 prompt、跑 loop、验证输出、持久化失败 tool result |
| `stardew-agent-registry.ts` | `Map<npcName, StardewAgent>` 实例缓存；per-NPC 对话锁；per-NPC tool-result 反馈队列（上限 10） |
| `stardew-tools.ts` | `buildStardewTools(ctx)` — 返回 9 个 Tool 定义（TypeBox schema） |
| `rule-engine.ts` | `RuleEngine.buildFallbackResponse(req, err)` — 将 `LLMBillingError`/`LLMUnavailableError` 映射为中文人设化兜底 speech |
| `output-validator.ts` | 校验 speech：非空 + CJK 比例 ≥ 0.3；构建 retry prompt |
| `prompt-builder.ts` | `PromptBuilder.buildDialogueSystemPrompt(...)` — 填充模板（角色规则、记忆、场景、tool-result 反馈） |
| `npc-prompt-loader.ts` | `NpcPromptLoader` — 同步读取 `data/npc_prompts.json`；按 friendship 选阶段 prompt |
| `world-snapshot-decoder.ts` | `decodeWorldSnapshot(snap)` — 校验 7 个必填字段，归一化类型 |
| `agent-memory.ts` | `AgentMemory` 实现 `MemoryBackend`；持久化到 `agentsDir/{npcName}_memory.json` |
| `types.ts` | 共享 wire 类型：DialogueRequest/Response、HelloRequest/Response、PingRequest/PongResponse、ToolCallResultMessage、ActionResultMessage、WorldSnapshot、SceneState、ToolAction |

**CLI 入口**：`valley-ai-server [options]`（位于 `packages/stardew/src/cli.ts`）

| Flag | Env | 默认 | 说明 |
|---|---|---|---|
| `--port` | — | `8765` | WebSocket 监听端口 |
| `--hostname` | — | `127.0.0.1` | 绑定地址 |
| `--data-path` | — | `../data/npc_prompts.json`（相对 exe） | NPC 提示词数据文件路径 |
| `--agents-dir` | — | `{cwd}/agents` | NPC 记忆持久化目录 |
| `--llm-api-key` | `LLM_API_KEY` | — | **必填**，缺失则 `process.exit(1)` |
| `--llm-model` | `LLM_MODEL` | `MiniMax-M2` | 模型 ID（C# 默认传 `MiniMax-M3`） |
| `--llm-base-url` | `LLM_BASE_URL` | `https://api.minimax.chat/v1` | OpenAI-compatible base URL |
| `--llm-provider` | `LLM_PROVIDER` | `minimax` | `openai`/`anthropic`/`google`/`deepseek`/`openrouter`/`lmstudio`/`minimax` |

**Wire 协议**（JSON over WebSocket text frames，camelCase）：

| `type` | C# 发送 → TS 响应 | 说明 |
|---|---|---|
| `hello` | `hello` (serverVersion: "0.1.0") | 握手 |
| `ping` | `pong` | 心跳 |
| `dialogue` | `dialogue_response` | **唯一的 LLM 触发消息**。请求字段：`requestId/npcName/playerInput/worldSnapshot`；响应字段：`requestId/npcName/speech/actions[]/emotion/memorySideEffect/fallback?` |
| `tool_call_result` | `ack` | C3 反馈环：C# 通知工具执行结果给 TS server，字段 `callId/success/result/npcName?/tool?` |
| `action_result` | `ack` | 同上（旧路径兼容） |

**重要**：TS server **只处理这 5 个消息类型**。Python 时代的 `decision` / `state_sync` / `friendship_eval` / `gift_eval` 已废弃——所有 LLM 评估统一通过 `dialogue` 请求触发，C# 端如果还在发这些旧消息类型会被 default 分支返回 `ack` 并丢弃（`requestId: "unknown"`）。

**工具注册表**（9 个工具，TypeBox schema，全 `visibility: "llm_visible"`）：

| Tool | 说明 |
|---|---|
| `speak` | NPC 说话；写入 `memory.addConversation("npc", text)` |
| `emote` | 表情气泡（24 个 emote ID） |
| `give_item` | 从背包给物品（扣减数量） |
| `give_gift` | 情感性送礼；写入 `memory.addMemory(...)` `importance=6, entryType="gift"` |
| `set_state` | 切换行为状态（IDLE/FOLLOW/FIGHT/FARM/FORAGE/MINE/TALK）；写入决策记忆 `importance=3` |
| `show_dialogue` | 主动发起对话（style: bubble/chat/dialogue_box） |
| `remember` | 写 SignificantMemory（category: relationship/life_event/trauma/achievement；emotional_weight: joy/sorrow/anger/fear/love/pride/surprise） |
| `forget` | 模糊子串删除 `shortTermMemories`（永不触碰 `significantMemories`） |
| `get_info` | 查询：date/nearby/memory/health/inventory/player/location |

**Agent 隔离**：
- `StardewAgentRegistry.agents: Map<npcName, StardewAgent>` — 一个 NPC 名一个实例，懒创建。
- `lockedNpcs: Set<string>` — 对话锁。同 NPC 串行；锁定时返回 `（{npcName} 正在思考...）` 兜底。
- 记忆路径：`{agentsDir}/{npcName}_memory.json`（C# 默认 `{mod dir}/agents/`）。
- `toolResultQueues: Map<npcName, ToolResultRecord[]>` — 上限 10，溢出丢最旧。

**NPC 提示词数据**：`packages/stardew/data/npc_prompts.json`（33 个 NPC：Abigail/Alex/Caroline/Clint/Demetrius/Dwarf/Elliott/Emily/Evelyn/George/Gus/Haley/Harvey/Jas/Jodi/Kent/Krobus/Leah/Lewis/Linus/Marnie/Maru/Pam/Penny/Pierre/Robin/Sam/Sandy/Sebastian/Shane/Vincent/Willy/Wizard）。

**好感度→阶段映射**（`npc-prompt-loader.ts`）：

|---|---|---|
| 0-250 | stranger | 陌生人 |

**C# 集成**（`ServerProcessManager.cs`）：

- **生命周期绑定 Mod（不绑定存档）**：游戏启动进档时 `EnsureRunningAsync` 拉起服务器；返回标题画面**不**杀服务器；只在 `Mod.Dispose`（游戏退出）时杀进程树。旧 bug：返回标题时 Dispose manager 导致 EventHandlerInitializer 持有的旧引用静默失效（`if (_disposed) return false`），再进档永远启动失败。
- **可见控制台窗口**（配置 `ServerConsoleWindow`，默认 true）：`UseShellExecute=true` 独立 cmd 窗口显示服务器 stdout/stderr，便于查看 Agent 纯逻辑报错；false 时隐藏窗口并把输出重定向到 SMAPI 日志。
- **代理坑（已修复）**：`WebSocketClient` 创建 `ClientWebSocket` 必须 `Options.Proxy = null`——默认走系统代理，本机装有 Clash/VPN 时 `ws://127.0.0.1` 被代理截胡，表现为裸 TCP 探测通但 WS 握手永远失败。
- **配置陷阱（已修复）**：`src/ValleyAgent/config.json` 模板已从 csproj 部署项移除——此前每次 `dotnet build` 都会把 17 字段模板覆盖到 Mods 目录的用户 config.json（清掉 LlmApiKey/ServerExecutablePath 等）。
- **exe 解析**：优先 `ModConfig.ServerExecutablePath`（绝对或相对 `ServerDirectory`/mod dir），其次默认 `{mod dir}/valley-ai-server.exe`。
- **进程 args**：`--port {ServerPort} --llm-api-key {apiKey} --llm-model {llmModel} --agents-dir "{agentsDir}"`（不传 `--data-path`，由 TS server 用 `defaultDataPath()` 解析）。
- **端口冲突**：`KillExistingServerOnPort` 跑 `netstat -ano` 找 `LISTENING` 行，`taskkill /F /PID {pid}` 清理。
- **Watchdog**：5s 轮询；进程死则 `OnCrashed` 事件 + 指数退避重启（5s/15s/45s），上限 `MaxRestartAttempts = 3`；60s uptime 后重置计数器。
- **就绪探针**：`WaitForServerReadyAsync` 用 `TcpClient.BeginConnect("127.0.0.1", port)` 每 500ms 轮询，上限 `StartupTimeoutSeconds`（注意：是裸 TCP 探测，不能检测 WS 握手层问题）。
- 服务端对任意 NPC 名 `getOrCreate` 独立上下文（含非 Agent NPC），记忆按 NPC 名隔离存储于 `agents/{npc}_memory.json`。

### 2.2 关键数据流

**对话流（v4.3 — 唯一的 LLM 触发路径）**：

```
Player clicks NPC
    → NPCDialoguePatch 拦截 / 玩家在 AgentChatMenu 发消息
    → C# 构建 DialogueRequest { npcName, playerInput, worldSnapshot }
    → WebSocket 发送给 TS Agent Server (type: "dialogue")
    → TS server: load agent memory → build system prompt → run agentLoop
        → LLM 调用 + tool_call 执行 (speak/emote/give_item/...)
        → output-validator 校验 CJK 比例 ≥ 0.3
        → rule-engine fallback on LLM 失败
    → WebSocket 返回 DialogueResponse { speech, actions[], emotion, fallback? }
    → C# CommandExecutor 执行 actions[] (即时工具: speak/emote/set_state)
    → C# 显示对话 (AgentChatMenu / DialogueBox)
    → 延迟工具 (move_to/harvest) 通过 state_sync 后续执行
    → C# 通过 tool_call_result 消息反馈执行结果给 TS server（C3 反馈环）
```

**礼物流（玩家→NPC）**：

```
玩家右键 NPC 持有物品
    → NPCGiftPatch 拦截
    → C# 直接计算 giftTaste 好感度变化（不调 LLM）
    → 记录礼物记忆（AgentBrain.AddMemory）
    → 触发 NpcEmotionEvent → EmotionAnalyzer 推导情绪
    → 后续 dialogue 请求时 TS server 看到更新后的 friendship
```

**礼物流（NPC→玩家）**：

```
TS Agent Server 决策: NPC 应该送礼
    → tool_call: give_gift(item_id, quantity)
    → C# CommandExecutor.ExecuteGiveGift
    → 创建物品 → 添加到玩家背包/丢地上
    → 记录记忆 + 情绪 (GiftGiven)
    → tool_call_result 反馈给 TS server
```

## 3. 核心设计原则

### 3.1 自主性 (Autonomy)

NPC 的行为由**内在驱动**，不是外部脚本：
- LLM 决定"大方向"（进入哪个状态）
- Handler 内部实现 ReAct 循环自主执行子任务
- 任务完成后**主动退出**，触发下一次 LLM 决策

**反模式**：NPC 进入 FARM 状态后无限循环 farming，直到 30 秒定时器触发才换状态。正确做法是：附近没有可收作物了，NPC 自己做收尾动作，然后主动退出 FARM。

### 3.2 性格一致性 (Personality Consistency)

所有行为必须符合角色设定：
- **第一人称提示词**：NPC以"我是XXX"的内心独白方式思考，不是被描述的对象
- **好感度分阶段注入**：陌生人/认识/朋友/亲密/伴侣，每个阶段独立内心独白
- **提示词只定义NPC是谁，不假设玩家做了什么** — 具体记忆由Agent运行时自己写
- **决策 prompt** 要求"Respond in character"
- **对话 prompt** 要求"You ARE {NpcName}, not an AI assistant"
- **行为约束**：害羞的 NPC 不会主动搭讪，暴力的 NPC 战斗更积极

**提示词数据源**：`D:\Source\ValleyAI\packages\stardew\data\npc_prompts.json`（33个NPC，每人5阶段：stranger/acquaintance/friend/close/partner）

### 3.3 记忆系统 (Memory)

NPC 需要记住和玩家发生的事：

| 记忆类型 | 存储位置 | 内容 | 有效期 | 压缩 |
|---------|---------|------|--------|------|
| 短期记忆 | `AgentMemory.short_term_memories` | 最近对话、事件 | 持久化 | importance+recency剪枝 |
| 长期记忆 | `AgentMemory.long_term_memories` | 重要事件摘要 | 持久化 | importance+recency剪枝 |
| **重要事项记忆** | `AgentMemory.significant_memories` | 里程碑事件（结婚、生子、创伤等） | **永不遗忘** | **永不压缩** |
| 对话历史 | `AgentMemory.conversation_history` | 最近对话 | 持久化 | 保留最近50条 |
| 友谊历史 | `FriendshipSystem` | 每次好感度变化记录 | 持久化 | — |
| 礼物历史 | `GiftSystem` | 每次送礼记录 | 持久化 | — |
| 决策历史 | `AgentMemory.decision_history` | 最近决策 | 持久化 | 保留最近20条 |
| 情绪历史 | `AgentMemory.emotion_history` | 情绪变化 | 持久化 | 保留最近20条 |

**SignificantMemory（重要事项记忆）**：
- 类似Soul.md概念：NPC生命中不可忘记的重大事件
- 由Agent运行时自主写入（通过`remember`工具），不由系统预设
- 触发条件由prompt中的指令引导：关系里程碑、重大事件、情感转折、创伤经历
- 永不压缩、永不遗忘，始终注入prompt
- `forget`工具只能删除普通记忆，不能删除SignificantMemory

**Agent自主记忆管理**：
- `remember`工具：Agent主动写入重要事项记忆（第一人称，带category和emotional_weight）
- `forget`工具：Agent主动删除不重要的普通记忆（模糊匹配，需提供reason）
- 所有记忆持久化到JSON文件（`agents/{npc_name}_memory.json`）

### 3.4 情绪系统 (Emotion)

NPC 有持续的情绪状态，影响行为和对话。**已实现**：`NpcEmotion` 枚举、`EmotionAnalyzer` 映射、`NpcEmotionEvent` 事件触发。

### 3.5 事件驱动决策 (Event-Driven Decision)

LLM 决策不是定时轮询，而是**事件触发**：

| 触发事件 | 触发条件 | 说明 |
|---------|---------|------|
| 定时保底 | 每 30 秒（1800 ticks） | 防止 NPC 长时间不决策 |
| 对话结束 | 玩家关闭 DialogueBox | 对话内容作为新 context |
| 任务完成 | Handler 检测到无目标 | 收尾动作后触发 |
| 战斗结束 | 附近无怪物 | 评估战后状态 |
| 收到礼物 | 玩家给 NPC 送礼 | 评估礼物，更新情绪 |
| 紧急事件 | 怪物出现在附近 | 立即切换到 FIGHT |

**ReAct 分层**：
- **战略层（LLM）**：决定"做什么大方向"（进入 FARM / FOLLOW / TALK）
- **战术层（Handler）**：进入状态后自主执行子任务（找作物→走→收→找下一个）
- **战术层退出条件**：目标耗尽 → 收尾动作 → 主动退出 → 触发战略层

### 3.6 Anti-WanderingSpouses 机制（已修复）

**AgentTickLoop.cs** 每 tick 对所有 Agent 执行 `npc.followSchedule = false`，对抗原版 NPC schedule 系统。

**为什么存在**：Stardew Valley 的 NPC 按 schedule 表移动。即使我们给 NPC 设了 PathFindController，游戏引擎也可能在下一帧替换成 schedule 路径。强制 `followSchedule=false` 阻止这一行为。

**历史问题**（已修复）：早期实现中此机制同时做了 `npc.controller = null` + `Halt()`，破坏正在运行的 PathFindController，形成创建-销毁死循环。

**当前实现**：
- `AgentTickLoop` 从 `ModEntry.cs` 提取为独立模块（`Core/AgentTickLoop.cs`）
- 只设 `followSchedule=false`，不碰 `controller`
- Controller 生命周期由 `MovementService` 统一管理（`Navigation/MovementService.cs`）
- 所有 Handler 通过 `IMovementService` 接口请求移动，不再直接操作 `npc.controller`

### 3.7 Vanilla-Release 机制（隐性设计）

`ModEntry.cs:1078-1096`：连续 N 次 LLM 决策返回 IDLE → 认为 NPC "不知道做什么" → 将控制权交还给原版 schedule。

```csharp
const int MaxConsecutiveIdleBeforeRelease = 3;
if (count >= MaxConsecutiveIdleBeforeRelease)
    _releasedToVanilla.Add(agent.NpcName);
```

**进入条件**：3 次连续 IDLE 决策（可由配置调整）

**行为**：
- NPC 从 `_releasedToVanilla` 移除 → controller=null → Halt() → 被原版 schedule 接管
- 任何非 IDLE 决策自动退出 release 状态

**保护机制**：
- Vanilla-release **只在 IDLE 状态触发**；活跃状态（`FOLLOW`, `FARM`, `FIGHT`, `MINE`, `FORAGE`, `TALK`）受保护，不会被释放
- 任何非 IDLE 决策自动退出 release 状态

    if (target == null)
    {
        // 无目标 → 收尾仪式 → 主动退出
        DoClosingRitual(npc, agent);
        agent.StateMachine.ForceTransition(AgentState.IDLE);
        return;
    }

    // 2. 如果已到达 → 执行动作
    if (IsAdjacent(npc.TilePoint, target.Tile))
    {
        if (CanAct(npc.Name, currentTick))
        {
            PerformAction(npc, target, agent);
            _lastActionTick[npc.Name] = currentTick;
        }
        return;
    }

    // 3. 如果卡住 → 传送辅助
    float dist = Vector2.Distance(npc.Tile, new Vector2(target.Tile.X, target.Tile.Y));
    if (dist <= 2.5f && IsStuck(npc.Name, currentTick))
    {
        npc.setTileLocation(new Vector2(target.Tile.X, target.Tile.Y));
        return;
    }

    // 4. 创建 PathFindController
    if (npc.controller is not PathFindController)
    {
        npc.Speed = 2;
        npc.controller = new PathFindController(npc, npc.currentLocation, target.Tile, 2);
    }
}
```

**各 handler 差异**：

| Handler | 目标查找 | 动作 | 收尾仪式 |
|---------|---------|------|---------|
| FarmHandler | `HoeDirt` 成熟作物 / 干燥土壤 | 收获 / 浇水 | 伸懒腰 emote + "收完了" |
| MineHandler | 可破坏石头 | 移除对象，掉落物品 | 擦汗 emote + "清完了" |
| ForageHandler | 可采集地面物品 | 移除对象，放入背包 | 拍背包 emote + "收获不错" |
| FightHandler | 最近怪物 | `damageMonster` 范围攻击 | 收剑 emote + 战后感叹 |
| TalkHandler | 玩家位置 | 头顶问候语 | —（持续状态） |

**目标选择策略**：返回**最近**目标（Manhattan 距离），而不是字典遍历的第一个。

**Handler 退出条件标准化**：
- Handler 必须先**执行收尾仪式**（emote + 说话），再 `ForceTransition(IDLE)`
- **不能**在还有合法目标时退出（防止重复收割 bug — 动作执行后需验证目标已被消耗）
- 退出后由 `OnStateChanged` 事件触发下一次 LLM 决策

### 4.7 AgentNavigator — 导航系统

**文件**：`ValleyAgent.Abstractions/Navigation/AgentNavigator.cs`

**职责**：

**跨地图流程（v4.3）**：

```

    → AgentNavigator 计算路径 Town → BusStop → Farm
    → 出发阶段（Departing）：NPC 走向当前地图出口（距出口 >10 格跳过）

    → 到达：warp 到目标地图入口瓦片（LocationGraph 最后一跳），走向玩家
    → FOLLOW 状态每 tick UpdateLocalFollowing 持续跟随（>5 格启动，<2 格停）

**v4.3 变更**：
- **无路径/动态地图不再即时传送**：统一走模拟旅行（隐藏 → 估计时长（2跳）→ 出现在入口 → 走向玩家），消除“玩家在门口看到 NPC 凭空出现”

- DayStarted 不再把 FOLLOW NPC 贴脸传送到玩家脚下：统一原版日程安置，跟随由正常跨图旅行恢复

### 4.12 AgentHealth — 健康系统（v4：事件驱动）

**文件**：`ValleyAgent/Core/AgentHealth.cs`

**v4 变更：事件驱动而非每帧计算**：

```csharp
// 事件驱动设计
public class AgentHealth
{
    private volatile bool _isDead;
    public event Action<NPC>? OnDeath;

    public void TakeDamage(int amount)
    {
        Health -= amount;
        if (Health <= 0)
        {
            _isDead = true;
            OnDeath?.Invoke(npc); // 触发死亡事件
        }
    }

    public void Respawn() { _isDead = false; Health = MaxHealth; }
    public void Heal(int amount) { Health = Math.Min(Health + amount, MaxHealth); }
}
```

**设计理由**：NPC 死亡是低频事件，每帧检测 `health <= 0` 浪费 CPU。事件驱动只在状态变更时更新。

## 5. 状态定义与行为规范

### 5.1 IDLE

**进入条件**：默认状态，任务完成后主动退出到此状态。

**行为**：
- 停止移动（`Halt()`）
- 清除 `PathFindController`
- 可以播放 idle 动画（四处张望、原地踏步）

**退出条件**：
- LLM 决策进入其他状态
- 玩家靠近（可选进入 TALK）
- 怪物出现（紧急进入 FIGHT）

### 5.2 FOLLOW

**进入条件**：LLM 决定跟随玩家。

**行为**：
- 同地图：PathFindController 跟随玩家
- 跨地图：AgentNavigator 智能 warp
- 距离玩家 < 2 tiles 时停止
- 距离玩家 > 5 tiles 时开始移动

**退出条件**：
- LLM 决定做别的事
- 玩家进入室内（NPC 等待或跟随）

### 5.3 FIGHT

**进入条件**：LLM 决定战斗，或怪物在附近（紧急反应）。

**行为**：
- 寻找最近怪物
- PathFindController 接近怪物
- 相邻后执行攻击（`damageMonster`）
- 攻击冷却 48 ticks（~0.8s）

**退出条件**：
- 附近无怪物
- NPC 血量过低（可选逃跑）
- LLM 决定退出

**战后收尾**：收剑 emote + 战后感叹（"搞定！" / "有点累..."）

### 5.4 FARM

**进入条件**：LLM 决定帮忙 farming。

**行为**：
- 扫描 15 tiles 范围内的成熟作物和干燥土壤
- 优先收获成熟作物，其次浇水
- 收获后尝试放入背包，满了则掉落地面

**退出条件**：
- 附近无作物（收完了 / 浇完了）
- LLM 决定退出

**收尾仪式**：伸懒腰 emote + "呼，都收完了" + 触发 LLM 决策

### 5.5 MINE

**进入条件**：LLM 决定挖矿。

**行为**：
- 扫描 12 tiles 范围内的可破坏石头
- PathFindController 接近石头
- 相邻后播放镐子动画，移除石头，掉落矿石

**退出条件**：
- 附近无石头
- LLM 决定退出

**收尾仪式**：擦汗 emote + "这里的石头终于清完了" + 触发 LLM 决策

### 5.6 FORAGE

**进入条件**：LLM 决定采集。

**行为**：
- 扫描 15 tiles 范围内的可采集物品
- 必须户外或矿洞
- 采集后放入背包

**退出条件**：
- 附近无可采集物
- LLM 决定退出

**收尾仪式**：拍背包 emote + "收获不错~" + 触发 LLM 决策

### 5.7 TALK

**进入条件**：LLM 决定和玩家说话，或玩家主动点击 NPC。

**行为**：
- PathFindController 接近玩家
- 相邻后面对玩家
- 头顶显示问候语（从预设数组随机选择，或 LLM 生成）
- **问候语冷却**：60 秒（3600 ticks），防止聊天框刷屏
- **TALK 超时**：30 秒后自动返回 IDLE，防止 NPC 卡在 TALK 状态

**退出条件**：
- LLM 决定退出
- 玩家离开（距离 > 5 tiles）
- **TALK 持续时间超过 30 秒 → 自动返回 IDLE**

**消息显示规则**：
- 玩家主动发送的消息：只显示在 AgentChatMenu 中，**不重复添加到 NPC 气泡或全局聊天框**
- Agent 主动说话（speak 工具调用）：同时显示在 AgentChatMenu、NPC 气泡、全局聊天框
- TalkHandler 的问候语：显示在 NPC 气泡 + 全局聊天框（冷却 60 秒）

| `DecisionIntervalMinutes` | 0.5 | LLM 决策间隔（分钟） | ≥0.1 |
| `NonAgentAIDialogueProbability` | 0.3 | 非 Agent NPC 触发 AI 对话的概率 | 0.0–1.0 |
| `ServerConsoleWindow` | true | Agent 服务器在独立可见 cmd 窗口运行（下次启动生效） | true/false |
| `NonAgentAIChatEnabled` | true | 非 Agent 村民原版对话后自动打开 AI 输入框 | true/false |

**运行时控制**：
- `ValleyAgentApi.PauseAllDialogue = true` — 立即暂停所有对话
- `ValleyAgentApi.DialogueCooldownMs = 30000` — 动态调整冷却时间

## 7. UI 规范

### 7.1 核心原则

**混合使用原生和自定义 UI 组件**：
- `AgentChatMenu` — 主对话 UI（自定义 `IClickableMenu`），支持自由文本输入和消息历史
- `ChatBox` — 聊天消息广播（`Game1.chatBox.addMessage`）
- `InventoryMenu` — 背包查看
- `DialogueBox` — 保留用于非 Agent NPC 的 AI 问候显示

### 7.2 对话流程

> ⚠️ 2026-07-18：v3.3 AgentChatMenu 已移除，当前实现见 §4.5（原生 DialogueBox + DialogueBoxInputPatch）。以下为历史流程存档，不再适用。

```
Player right-clicks NPC
    ↓
NPCDialoguePatch.Prefix intercepts
    ↓
获取 AI 问候语 DialogueBox（缓存或 RAG fallback）
    ↓
问候关闭后 → AgentDialogueBoxClosePatch 触发 → 打开 AgentChatMenu
Player types message → Send
    ↓
AgentChatMenu 进入 waiting 状态（显示 "...thinking"）
    ↓
ValleyAgentApi.TryGenerateDialogue()
        → 检查冷却期（30s）→ 检查 pending flag → 通过
        → 异步调用 LLM（WebSocket）
    ↓
菜单冻结等待（最长 20s 超时，可按 ESC 取消）
    ↓
LLM response ready → PushResponse(npcName, text)
        → 检查全局去重 → 通过
        → 添加到菜单消息列表 → 解锁输入
    ↓
FriendshipSystem evaluates content
    ↓
Content added to short-term memory
    ↓
Triggers event-driven LLM decision
Player closes menu → EndTopicConversation
    → 恢复 pre-dialogue 状态（如 FARM/FOLLOW）
    → 不自动重新打开菜单（需玩家再次点击）
```

### 7.3 AgentChatMenu 实现

自定义 `IClickableMenu`，包含：
- NPC 头像和名称显示
- 消息历史列表（玩家消息右对齐，NPC 消息左对齐）
- "thinking..." 打字动画（NPC 正在生成回复时）
- 文本输入框和发送按钮
- 支持键盘 Enter 发送
- 菜单保持打开状态，不弹窗不切换

```csharp
var chatMenu = new AgentChatMenu(npc, greeting);
Game1.activeClickableMenu = chatMenu;

// LLM 回复通过 PushResponse 推送
chatMenu.PushResponse("你好！今天天气真不错。");
```

### 7.4 ChatBox 消息规范

只有以下情况发送消息到 `Game1.chatBox`：
- Agent **主动说话**（speak 工具调用）
- TALK 状态的问候语（冷却 60 秒）
- **系统消息（灰色斜体/灰色普通字，非 NPC 发言）**：仅用于玩家必须知情但不该由 NPC "说"出来的机械事件，例如 Agent 模式退出（`*海莉离开了*`）、跨图跟随丢失等。样式与 NPC 彩色发言明确区分
- **不发送**：
  - 玩家主动发送的消息（已在 AgentChatMenu 中显示）
  - LLM 回复内容（仅在 AgentChatMenu 中显示）
  - 收获提示、挖矿提示、战斗提示
  - 决策 thought
  - **地图切换播报**：跟随中的跨图旅行全程静默，禁止"我马上来"/"我到了"类消息——切图是高频操作，每次都说话等于刷屏（2026-08-02 拍板）

**消息去重原则**：
- 玩家输入的消息只在 AgentChatMenu 中显示，**不重复推送到 NPC 气泡或全局聊天框**
- Agent 主动说话（通过 speak 工具调用）同时显示在：AgentChatMenu、NPC 气泡、全局聊天框
- 同一条消息（相同 NPC + 相同文本）不会重复添加到任何 UI 层级

颜色：根据 NPC 名字哈希生成一致的 pastel 色。

## 8. 性能与 Token 优化

### 8.1 分层决策策略

```
高频（每 tick）    → 本地代码：目标扫描、路径规划、碰撞检测
                    不问 LLM

中频（每 30s）     → 轻量 LLM：输出 JSON intent（targetState + reason + thought）
                    Token 约 200-500

低频（事件触发）   → 完整 LLM：深度对话生成、情感分析、复杂决策
                    Token 约 1000-2000
```

### 8.2 缓存机制

| 缓存内容 | 位置 | 有效期 |
|---------|------|--------|
| 问候语 | `NPCDialoguePatch._greetingCache` | 当天 |
| 决策结果 | `AIDecisionEngine` 内部 | 5 分钟 |
| 环境扫描 | `FarmHandler.ScanEnvironment` 等 | 10 秒 |
| RAG 数据 | `RAGKnowledgeBase`（内存加载） | 整个会话 |

### 8.3 Token 预算

- `ModConfig.TokenBudget = 0`（默认无限制，但建议设置上限）
- 每轮对话预算：~2000 tokens
- 每次决策预算：~500 tokens
- 熔断器：连续 5 次失败则暂停 LLM 调用（`CircuitBreakerThreshold = 5`）

### 8.4 性能红线

- `OnUpdateTicked` 每 tick 执行时间 < 1ms
- LLM 调用全部 async，绝不阻塞主线程
- `PathFindController` 不频繁重建（只在缺失时创建）
- 死亡 NPC 移出地图，停止所有更新

### 8.5 常量配置

**文件**：`ValleyAgent/constants.json`

所有硬编码的魔法数字已编录到 `constants.json`，按子系统分类：

| 分类 | 关键常量 |
|------|---------|
| `ai` | `decisionIntervalMinutes=0.5`, `circuitBreakerThreshold=5` |
| `dialogue` | `cooldownMs=30000`, `temperature=0.7`, `nonAgentAIDialogueProbability=0.3` |
| `handlers` | `actionCooldownTicks=48` (通用), `scanRadius=12-15`, `debugLogCooldownTicks=60` |
| `movement` | `stuckDistanceThreshold=2.5`, `stuckTimeThresholdTicks=120`, `shortRangeCooldownTicks=5`, `longRangeCooldownTicks=30` |
| `combat` | `monsterAttackCooldown=90`, `monsterDamage=8`, `monsterAggroRange=10.0` |
| `stateDurations` | `FIGHT=15s`, `FARM=8s`, `MINE=10s`, `FORAGE=8s`, `FOLLOW=3s` |
| `talk` | `cooldownTicks=3600` (~60s), `maxDurationTicks=1800` (~30s auto-exit) |

> **Note**: `constants.json` 是只读编录。运行时调整请通过 `ModConfig`（`config.json`）或 SMAPI 的 Generic Mod Config Menu 进行。

### 9.5 关键设计决策（v4 新增）

#### 为什么 TS 做智能层？（v4.3 重写自 v4.1 的 Python 时代）

- TypeScript 生态有 Vercel AI SDK v5 + @ai-sdk/openai/anthropic/google 等 provider 包，原生支持 tool_calling、流式、circuit breaker
- C# 的 LLM 生态薄弱，之前手搓的 `ILLMProvider` 代码冗余且难维护
- Bun 编译为单文件 `valley-ai-server.exe`，C# `ServerProcessManager` 自动拉起/重启，无需用户手动启动 Python
- 双系统冗余消除：不再有 C# 和 TS 两套决策/对话/友谊/礼物系统
- 模型/Provider 切换通过 CLI flag 或 env var（`--llm-provider minimax|openai|...`），无需重编译

#### 为什么删除 LocalFallbackProvider？（已删除）

- C# 端不再有任何 LLM 调用能力，fallback 没有意义
- 如果 TS Agent Server 不可用，NPC 回退到规则引擎（`RuleBasedDecisionEngine`），不尝试本地 LLM
- 简化了 `DualPathAgentServerProvider`，不再需要降级链
- `DualPathAgentServerProvider` 现在仅封装 `WebSocketClient`，无 fallback 层

#### 为什么移除 THINKING 状态？（✅ 已完成）

- 思考不应阻断行动——NPC 在等待 LLM 决策时仍可移动和执行操作
- 决策完全异步，不需要冻结 NPC
- 消除了每帧锁定位置到 anchor 的性能开销

#### 为什么死亡检测改为事件驱动？

- 每帧检测 `health <= 0` 是浪费——NPC 死亡是低频事件
- 事件驱动：`TakeDamage` 中设置 `_isDead = true`，只在状态变更时更新
- 复活同理：`OnDayStarted` 或 `Respawn` 事件中设置 `_isDead = false`

#### 为什么引入 ServiceContainer？

- `ModEntry` 之前管理 20+ 个私有字段和服务实例，是典型的上帝类
- 依赖注入让服务之间的依赖关系显式化
- 新增子系统只需在 `ServiceInitializer` 中注册，不需要修改 `ModEntry`

**已修复的旧问题**（v4 重现）：
- ~~对话/决策依赖 Python WebSocket~~ → v4.3 正式确立 TS 智能 + C# 执行的双层架构
- 记忆无压缩 → 已实现 LLM 压缩 + fallback 重要性剪枝
- 情感无强度 → 已实现 `EmotionState(primary, intensity, source)`
- C#/Python 双系统冗余 → v4 统一：所有 AI 逻辑在 TS server，C# 只做执行
